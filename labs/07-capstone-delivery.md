# 综合交付 · 完成一次可交接交付

**难度：中级到高阶**　**预计：60–150 分钟**　**动作：5**　**主风险：一个会话里同时重开计划、实现、评审和发布**

> **完成时：** 你会交付一条用户可见的垂直行为，以及一套能被新会话接手的规格、验证、review 与 handoff。

## 开始前

- 已完成实践关卡 2、4、5、6 的产物，或能提供等价证据；
- 一张边界清楚、低风险且可独立验证的 ticket；
- 非生产分支与项目约定的最小验证命令。

## 任务

选择一个真实但低风险的 ticket，完成一次小型垂直切片。综合交付检验的是你能否串联既有能力，不是一次性吸收新概念。

## 不做

- 不在本关发布生产、读取凭据、删除数据、付款或升级权限；
- 不重新讨论已确认的业务范围；
- 不以“所有检查大致通过”替代用户可观察的验收。

## 操作

### 1. 重读输入并确认边界

只读取 spec、ticket、当前分支和约定的测试 seam。目标、验收或明确不做不清楚时，退回实践关卡 2。

### 2. 建立或确认目标反馈

若是 bug，复用实践关卡 3 的红色命令；若是新行为，先写出用户操作与预期结果，再建立可复跑检查。

### 3. 完成一条垂直行为

围绕一个用户可观察结果实现最小改动。每次改动后运行目标检查，最后补充分支适用的类型、lint 或集成检查。

### 4. 完成双轴 review

复用实践关卡 5 的 Standards 与 Spec 轴。发现阻塞问题时修复并重新验证；没有 finding 时写出通过依据。

### 5. 写 handoff 并独立复述

按实践关卡 6 产出 handoff。让新会话或同事只读它后复述当前状态，再决定维护者是否合并、发布或执行人工步骤。

## 必须留下的产物

- spec 与 ticket 的最终链接；
- 当前分支上的最小验证与补充检查结果；
- Standards 与 Spec 两份独立 review 结论；
- 可被新会话复述的 handoff。

## 验收

- 新会话无需阅读原聊天，也能执行唯一下一步；
- 用户承诺、最小验证与 review 结论能互相追溯；
- 未授权的外部操作没有被执行；
- 当前验证新鲜可复跑，风险仍明确可见。

## 停止条件

交付包完整、验证通过且 handoff 已被独立复述时停止。是否合并、发布或执行外部人工步骤，由项目维护者在本关之外决定。
