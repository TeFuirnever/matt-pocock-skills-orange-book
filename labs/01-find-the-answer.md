# 实践关卡 1 · 先找到答案

**难度：小白**　**预计：30–45 分钟**　**动作：3**　**主风险：把能查的事实丢回给人**

> **本关完成时：** 你会得到一份能让新会话复述“已确认什么、由谁决定什么、这次做什么”的决策记录。

## 任务

任选一个小 UI 任务，例如“把设置页按钮文案改为保存并验证”。先不要修改代码。你要确认这个文案是否与现有行为一致，并判断这到底是纯文案修改还是新增功能。

## 开始前

- 一个可运行的本地仓库与非生产分支；
- 一个已知界面位置或搜索关键词；
- 项目自己的最小验证命令。

## 不做

- 不修改产品代码、测试或本地化文件；
- 不替负责人决定业务取舍；
- 不把调查扩张成完整实现计划。

## 操作

### 1. 写出待回答问题

把任务拆成三类，不要混写：

| 类型 | 必须回答的问题 | 谁回答 |
|---|---|---|
| 环境事实 | 文案来自哪里？点击现在触发什么？哪些语言受影响？ | Agent 调查并给出文件、代码或命令证据 |
| 人类决策 | “验证”是否应成为本次交付承诺？没有该行为时是否扩 scope？ | 负责人确认 |
| 规格结论 | 这次改什么、不改什么、如何验证？ | 写入记录，供下游使用 |

### 2. 运行最小调查

让 Agent 使用仓库搜索、目标组件阅读、现有测试和 i18n 资源，而不是询问你“项目用什么框架”。要求每一个环境事实附一个可复查定位，例如文件路径、符号名或命令输出摘要。

### 3. 写入决策记录

在你选择的项目文档目录新建一份短记录，至少包含：

```markdown
# <任务名> 决策记录

## 已确认事实
- <事实>：<证据定位>

## 人类决定
- <决定及原因>

## 本次范围
- 做：<可观察变化>
- 不做：<明确排除项>

## 验证
- <一条当前可运行的命令>
```

## 必须留下的产物

- 一份包含“已确认事实 / 人类决定 / 做与不做 / 验证”的决策记录；
- 一条能在当前分支运行的最小验证命令；
- 一句明确结论：这是文案修改，还是功能变化。

## 验收

- Agent 没有把代码、测试或本地化文件中可查的问题抛给人；
- 文案承诺与现有行为一致，或者范围已被明确升级；
- 新会话只读决策记录，也能复述本次做与不做；
- 没有为“先调查”写入任何产品代码。

## 停止条件

决策记录被确认后停止。若出现新的业务取舍，不要边查边改；先更新记录，再进入实践关卡 2。
