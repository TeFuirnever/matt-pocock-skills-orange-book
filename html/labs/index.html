橙皮书实践路径

这不是书外附录。实践路径把正文中的关键判断变成你在自己仓库里可复跑、可交接的动作。

开始前，选一个非生产分支和一个可以独立验证的小改动。不要把第一次练习用在发布、凭据迁移、删除数据或不可逆的线上操作上。

三层练习

  • 章内微练习： 5–10 分钟，只验证一个概念，得到一个立刻可观察的结果；它不阻塞阅读。
  • 实践关卡： 20–45 分钟、3–5 个动作，留下一个下一关可复用的产物。
  • 综合交付： 60–150 分钟，把已完成关卡组合成一次小型、可 review 的交付。

六个实践关卡

实践关卡 1 · 先找到答案

把环境事实、人类决策和范围结论分开。产物：决策记录 + 最小验证命令。

实践关卡 2 · 把决定写成可施工规格

把已确认的决定压缩为 spec 与第一张垂直 ticket。产物：spec + tracer-bullet ticket。

实践关卡 3 · 让一个 bug 先变红

把症状变成一条穿过公共 seam 的失败命令。产物：红色结果 + 可重复症状。

实践关卡 4 · 用最小修复闭合证据

用同一条命令从红到绿，并固化回归。产物：最小 diff + 红绿证据 + 回归检查。

实践关卡 5 · 分开两条 review 轴

分别审查工程标准与用户承诺。产物：Standards 与 Spec 两份结论。

实践关卡 6 · 交接前先复述

让新会话只读交接包后复述状态与唯一下一步。产物：可验证 handoff。

综合交付 · 完成一次可交接交付

选择一个真实但低风险的 ticket，串联规格、实现、双轴 review 与 handoff。它不是第七个大关卡，而是六关完成后的综合练习。

通用规则

  1. 一关只解决一个问题。 发现目标变化，回到实践关卡 1 或 2，不在实现中悄悄扩张范围。
  2. 事实先查，取舍再问。 代码、日志、文档和命令能回答的事，由 Agent 带着证据回来。
  3. 每关都有停止条件。 达到验收后停止；未达到则保留失败证据，不用“差不多”通过。
  4. 下一关只读取产物，不读取整段聊天。 让 decision.md、spec.md、ticket、测试命令和 handoff.md 成为工作记忆。

通过标准

完成六个实践关卡和综合交付，不等于背下所有 Skill 名。你应该能够用一个真实小任务展示：谁负责事实调查、谁做取舍、什么命令能从红变绿、两条 review 轴怎样独立成立、下一位协作者从哪里继续。
