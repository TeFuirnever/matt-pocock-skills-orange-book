实践关卡 5 · 分开两条 review 轴

难度：中级　预计：30–45 分钟　动作：3　主风险：把“代码干净”误当成“需求做对”

本关完成时： 你会得到两份互不替代的 review 结论：一份检查工程标准，一份检查用户承诺。

开始前

  • 一条已完成、可运行的垂直行为；
  • 该行为对应的 spec、ticket 与新鲜验证结果；
  • 一个可供 review 的 diff 或变更集。

任务

把 review 拆为 Standards 与 Spec 两个问题。前者检查实现是否遵守项目边界，后者检查用户可观察结果是否兑现；任一结论都不能替代另一个。

不做

  • 不只写“LGTM”“代码干净”或泛泛赞语；
  • 不以旧测试结果、主观印象或完整聊天作为 review 证据；
  • 不在 review 中悄悄改变已确认的范围。

操作

1. 固定 review 输入

把 spec、ticket、diff、目标命令和本次结果排在一起。缺少任一项时，先补输入而不是开始评论代码风格。

2. 完成 Standards review

只回答类型、安全、错误处理、边界、测试 seam 与项目约定是否满足。每个 finding 必须指向文件、行为和最小修复；没有 finding 也要写明依据。

3. 完成 Spec review

只回答用户故事、明确不做、验收与可观察交互是否满足。确认没有把“实现合理”误当成“用户结果正确”。

必须留下的产物

  • Standards review：通过或有定位的 finding；
  • Spec review：通过或有定位的 finding；
  • 每条 finding 对应的证据与下一步；
  • 仍存在的风险或明确“无”。

验收

  • 两份结论使用不同的问题与证据；
  • 任何阻塞 finding 都能回到具体 seam、行为或范围；
  • 两条 review 轴都没有把发布授权当作普通代码检查；
  • 读者可从结论判断该继续修复、交接还是停止。

停止条件

两条 review 轴均已得到明确结论，且下一步唯一动作可被写成一句话时停止。
