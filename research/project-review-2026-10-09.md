# 橙皮书独立质量审查 · 2026-10-09

## 结论

当前项目已经具备结构清楚、可追溯、可构建的中文工程手册基础，但还不能用“38 项覆盖齐全、check 通过”证明它是一套新手可独立完成的教程，或一个经过交互与无障碍验证的阅读产品。最需要改善的是**源行为契约、练习可运行性、内容检索与发布门槛**，不是先换视觉风格或换文档框架。

本轮没有发现需要立即停止整站使用的 P0。确认的 P1 涉及读者会照做的错误约束、首次练习阻塞、搜索漏项、屏外键盘焦点，以及检查无法拦截实际故障。建议先完成下列五个交付包：

1. 纠正源语义与权限失败分支，统一当前基线。
2. 修复完整 Skill 标题索引及移动目录焦点。
3. 为现有发布检查补链接、锚点和最小浏览器行为测试。
4. 选定一条贯穿练习，提供可复现起点与成功/失败样例。
5. 建立可复跑的本地源同步审查与版本发布合同。

## P1：应优先修复

### R01 · 权限拒绝被写成可换工具继续

**证据：** `chapters/14-operation-cases.md:292` 的失败表把“编辑工具拒绝目标路径”统一映射为“换可审查的编辑通道，保留同一补丁目标”。

**影响读者：** 跟随操作案例的新手或 Agent。它可能把沙箱/审批拒绝误判为编辑器能力限制；本轮没有声称现有执行发生越权。

**根因：** 降级策略没有先识别失败类别。授权边界与工具功能被混在一起。

**建议：** 区分已授权操作的编辑器能力缺失，与权限/审批拒绝。前者可以换等价工具；后者停止被拒动作、报告准确原因，继续不受影响的只读工作，取得合法授权后再继续。

**验收：** “编辑 API 不支持格式”与“受限目录拒写”两例得到不同处理；全文相近的失败恢复建议也经过核对。

**依赖/量级：** 无依赖，S（0.25–0.5 人日）。这是先于排版优化的内容修复。

### R02 · glossary 验收要求与上游定义冲突

**证据：** `chapters/12-skill-handbook.md:357`、`:363` 要求术语交叉引用代码，并要求词条包含“定义、正例、反例和代码指针”。源 `skills/engineering/domain-modeling/SKILL.md:56–64` 把代码核实作为研讨过程，并明确 glossary 不含实现细节；`GLOSSARY-FORMAT.md:12–29` 为 1–2 句定义加 `_Avoid_`。本书 `chapters/07-code-quality.md:16` 的词典边界也与此不一致。

**影响读者：** 按手册产物验收写领域文档的人，会被鼓励把实现导航混入词义，或把符合源模板的简洁词条判为不合格。

**根因：** 把会话中用于验证的证据误转为长期词汇表字段。

**建议：** 给出与固定源模板一致的匿名词条；正反例用于推敲词义，代码证据存放在合适的调查/导航文档，不作为 glossary 必填字段。

**验收：** 全书词条示例不强制代码指针，包含必要的 `_Avoid_`；过程与产物字段清楚分离。

**依赖/量级：** 无外部依赖，S。

### R03 · triage 可照做条目漏掉状态与公开输出合同

**证据：** `chapters/12-skill-handbook.md:119–130` 只概括核查、建议与 brief。源 `skills/engineering/triage/SKILL.md:13–16` 要求发布内容的 AI 声明；`:26–45` 要求 category/state 各恰好一个，冲突先问维护者，needs-info 有回复后回 needs-triage。书中没有等价声明或完整不变量。

**影响读者：** 维护者可能发出与源行为不符的评论，或留下互斥状态共存的工单；“每项有状态”不足以检验状态正确。

**根因：** 条目覆盖活动名称，却省略外部产物与状态机的硬约束。

**建议：** 补最小状态表、角色到真实标签映射、冲突停止条件和带 AI 声明的匿名 brief；用本地样例演练，不实际外发。

**验收：** 正常、标签冲突、needs-info 回复三例都能判定下一步；每个对外输出样例具备源要求的声明。

**依赖/量级：** 核对源 `AGENT-BRIEF.md`，S–M。

### R04 · 六关路线在第二关后丢失连续任务

**证据：** `labs/01-find-the-answer.md:9` 允许纯文案修改；`labs/02-decision-to-spec.md:15` 要求沿用前关决策，`:72` 引向第三关；`labs/03-red-green-bug.md:9`、`:15` 却要求已有且可重复的小 bug。

**复现：** 选择“已有验证行为，只改按钮文案”，完成前两关后没有第三关所需 bug。换成保存重启失效又使原决策和规格失去连续性。

**影响/根因：** 小白与课程组织者无法按承诺连续完成；新功能交付和故障诊断被强行拼成单线。

**建议：** 选择一个贯穿任务，或在第二关后显式分成“新行为/TDD”与“已有 bug/诊断”两路，在 review 汇合；换题时明确重建哪些输入。

**验收：** 文案、新行为、已有 bug 三种起点都能走到完成，每关输入来自前关或明确的切换步骤，不靠读者自行补题。

**依赖/量级：** 先定课程主线，M。

### R05 · 新手教程缺少可运行起点和固定版本复现路径

**证据：** `chapters/01-reading-guide.md:22–27` 将不会指出验证命令的人归入小白路径；`labs/01-find-the-answer.md:13–15` 已要求运行仓库和最小验证命令，第二关又要求 seam。`chapters/14-operation-cases.md:212` 仍需读者自行替换路径/API。仓库没有配套 starter、fixture 或 solution 工程。`chapters/03-installation.md:24–62` 提供跟随最新的安装入口，并诚实提示不锁定教材提交，但没有给可操作的比对与回退到基线的方法。

**影响/根因：** 有经验读者可把它用作迁移指南；没有可测试项目的人无法获得第一次成功。固定版教材与浮动安装同时存在，却没有实验基线。

**建议：** 提供小型匿名离线练习工程：已知缺陷、目标命令、预期红/绿输出、重置方式；先完成一次确定的示范，再迁移到自己的仓库。安装页分开“跟随最新使用”和“复现本版”，给经实际验证的源 commit 核对步骤，不假定所有客户端支持同一个 pin 参数。

**验收：** 新环境中不靠作者补充命令即可完成第一关；实际源 commit 可记录；最新版差异有处理分支。用至少两名新读者试读记录卡点与耗时。

**依赖/量级：** 依赖 R04 与客户端能力核实。最小 fixture/教程 L，安装复现 M；若不做 fixture，应先收窄“小白独立教程”的承诺。

### R06 · 精确 Skill 搜索漏掉最相关小节

**实现证据：** `html/site.js:16–18` 只索引 h2/h3；`:69` 只取首个文本节点作为标题。含 code 的标题“7.5 `wait-what`：…”被截成“7.5”，而 38 项逐项条目使用 h4。

**用户 Mac 实测：** 搜索 `tdd` 出现只有“4.4”“5.2”的结果标题；搜索 `wait-what` 返回第 1 周、Productivity 大类和附录，却没有第 7.5 小节。搜索 `chief-of-staff` 命中的是整个 11.4 实验分类，而非该 Skill 条目。

**影响/根因：** 最需要参考手册的读者不能直接找到条目；有命中不等于检索任务完成。标题提取错误与索引粒度过粗共同造成。

**建议：** 提取去掉锚点按钮后的完整标题；将 Skill 条目作为独立搜索单元，保留所属章/分类上下文，精确名称优先。避免把每个无意义的低层标题都加入结果。

**验收：** `wait-what`、`tdd`、`pr`、`chief-of-staff` 的前列结果有完整标题，点击后定位对应条目；结果集有 DOM 行为回归测试。

**依赖/量级：** S–M；与 R08 一起固化。

### R07 · 移动目录关闭后仍可进入屏外焦点

**实现证据：** `html/print.css:1027–1045` 用 transform 移出视口；`html/site.js:20–26` 只改 class/expanded/遮罩，无隐藏交互语义或焦点管理。

**用户 Mac 实测：** 390px 宽度，目录关闭，从“打开搜索”按钮按 Tab，焦点进入“小白：先选路径”；其矩形为 left=-318、right=-35，菜单 `aria-expanded=false`。辅助技术 DOM 树中仍包含整个目录。

**影响/根因：** 外接键盘、键盘导航和读屏用户会经过不可见链接，无法确认焦点位置。视觉隐藏未同步到交互状态。

**建议：** 采用清楚的 disclosure 或 modal drawer 模式；关闭时目录不可聚焦，打开与关闭有可预测的焦点路径。若采用模态模式，还要正确处理背景区域；不能只补一个 aria 标签。

**验收：** 320/390/780px 关闭目录时 Tab 不进入内部；打开、Esc、选链接与遮罩关闭均焦点可见；781px 恢复桌面目录的正常可用性。

**依赖/量级：** M，配合键盘浏览器回归。与 WCAG 焦点相关要求映射，但本轮不据此宣称整站合规或不合规等级。

### R08 · 检查允许断链与整页阅读交互崩溃通过

**证据：** 两项单测仅检查 URL 分类；`scripts/verify-public.mjs:305–398` 主要检查字符串存在。前述临时副本同时加入无目标锚点和 site.js 顶层异常，完整 check 仍通过。

**影响/根因：** 发布绿灯可能伴随搜索、菜单等完全失效；校验目标偏向实现形状，而不是用户可观察结果。

**建议：** 保留静态合同，加本地链接/锚点遍历与少量浏览器冒烟：页面无未处理启动异常、精确 Skill 搜索、目录打开关闭、键盘路径、主题切换。先覆盖现有真实缺陷，不堆截图数量或 CSS 字符串。

**验收：** 两种故障分别注入时都必须失败；恢复后通过；正常检查覆盖主阅读版与独立练习页。

**依赖/量级：** 选择轻量浏览器测试方式，M。是后续内容与UI修改的防回归基础。

### R09 · 贡献指南仍指向旧基线

**证据：** `CONTRIBUTING.md:8–9` 要求 `6654f6b…`，现行 AGENTS、README、manifest 为 `b0618bc…`。

**影响/根因：** 新贡献者可能用旧规则修正当前正文。同步覆盖了主要阅读入口，却未把维护入口纳入当前版本合同。

**建议：** 当前指南引用一个统一基线来源；历史研究保留原日期/commit，不能全局替换旧 hash。

**验收：** 所有“当前基线”规范文件一致；历史证据仍明确标作历史；改错当前 hash 的变异被检查捕获。

**依赖/量级：** S，与 R12 的同步机制衔接。

## 需要进一步验证而不应冒充结论的事项

1. **锚点落点偏移。** 用户 Mac 窄屏切换并直接访问第14章锚点后，所有25张图加载完成，目标标题仍在视口下方约2394px；URL已是目标。25张图都没有 width/height 属性（CSS:734–738仅auto/max-width），可能涉及图片布局变化与长距离滚动。但本轮没有隔离冷加载、缓存、滚动恢复和视口切换变量，因此记录为待稳定复现的 P2 候选，不当成已确定根因。验收应覆盖冷加载深链与目录点击两种路径。
2. **完整读屏与对比度。** 已证实屏外键盘焦点；未启用 VoiceOver 或修改系统减少动态效果设置，未做颜色量测，不能凭截图宣称 AA。
3. **打印与长文信息密度。** 781px使用桌面目录，正文列约477px（内部留白后更窄），780px切移动模式后内容宽780px。断点突变是可观察现象，但是否改到更高阈值需阅读任务验证，不能仅凭审美定为P1。
4. **实际新手成功率。** 缺 fixture 是明确交付缺口，完成时长与学习迁移效果仍需真人试读，不能从文字质量推算。
